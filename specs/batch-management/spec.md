# 批次管理 · 功能规范（spec）

- **模块**：batch-management
- **对应页面**：`src/pages/Batches.jsx`
- **依赖**：`specs/constitution.md`
- **版本**：v1.0 · 2026-08-26
- **状态**：Phase 0 原型已实现台账与展开；本文档按工业级产品规格补全追溯与状态机

## 1. 概述（Overview）

批次管理是 FluxMES 的「生产执行」核心，管理从开工到入库的全生命周期批次记录。原型提供批次台账（批号/产品/配方/设备/工序/参数/进度/状态/开工时间）、状态筛选、关键字搜索，以及点击行展开查看「工艺路线」与「批次档案」。工业级需补齐：批次状态机、工艺路线驱动、原料/配方/操作员结构化关联、异常终止与偏差、正向+逆向追溯、入库联动与放行审计。

## 2. 用户场景（User Scenarios）

- **US1 · 工艺员查看在制批次**：张伟在台账中按「进行中」筛选，找到 B-260826-014，展开查看发酵工序进度与关键参数（pH 2.05 / 36.8°C / DO 34%）。
- **US2 · 质量追溯**：质检员林晓芸点击 B-260826-007 的「批生产记录」，调阅全工序参数与检验结论，准备放行。
- **US3 · 异常处置**：B-260825-028 发酵第 38h 染菌异常终止，工艺组发起偏差调查（EX-260825-003），系统标记状态为 abnormal 并锁定后续工序。
- **US4 · 新建/排产**（工业级）：计划员导入生产计划批量创建批次，或手工新建并绑定配方版本与原料批号。
- **US5 · 逆向追溯**（工业级）：监管/客诉触发，由成品批号一键反查所用原料批号、设备与班次。

## 3. 功能需求（Functional Requirements，EARS）

- **FR-1** WHEN 用户进入批次管理，THE SYSTEM SHALL 以表格展示批次台账，列含批号、产品、配方、设备、当前工序、关键参数、进度、状态、开工时间。
- **FR-2** WHEN 用户选择状态分页签（全部/进行中/待检/已完成/异常），THE SYSTEM SHALL 仅展示匹配状态的批次并展示各状态计数。
- **FR-3** WHEN 用户在搜索框输入关键字，THE SYSTEM SHALL 按批号/产品/设备/配方模糊过滤（不区分大小写）。
- **FR-4** WHEN 用户展开某批次行，THE SYSTEM SHALL 展示该批次的工艺路线（各工序 done/active/fail/todo 状态）与批次档案（配方、原料批号、操作员、计划产量等）。
- **FR-5** WHEN 批次处于异常（abnormal），THE SYSTEM SHALL 在状态与进度上以危险色标记，并提示关联偏差单号，禁止推进后续工序。
- **FR-6** WHEN 用户点击「批生产记录」，THE SYSTEM SHALL 打开该批次的全工序电子记录（参数时间序列 + 操作事件 + 检验结论）。
- **FR-7** WHEN 用户点击「导出」，THE SYSTEM SHALL 导出该批次档案为可归档文件（PDF/Excel），内容含 constitution C2 要求的完整字段。
- **FR-8** WHEN 用户点击「新建批次」，THE SYSTEM SHALL 打开创建表单，必填配方版本、产品、计划产量与关联原料批号，提交后生成批次号并进入「进行中」。
- **FR-9**（工业级）WHEN 用户导入生产计划，THE SYSTEM SHALL 批量创建批次并校验与配方/物料可用性的一致性。
- **FR-10**（工业级）IF 批次所有工序完成且成品检验合格，THE SYSTEM SHALL 将其置为「待放行」并阻断未授权修改（只读 + 审计）。
- **FR-11**（工业级）WHEN 用户执行任意批次状态变更，THE SYSTEM SHALL 记录审计日志（操作人/时间/前后状态），满足 C3。
- **FR-12**（工业级）WHEN 用户发起追溯查询，THE SYSTEM SHALL 在单次操作内返回该批次的正向链路（原料→工序→设备→检验→入库）与逆向链路（成品→原料批号）。

## 4. 非功能需求（Non-Functional Requirements）

- **NFR-1** 台账在 1k 行规模下滚动流畅；服务端分页，单页 ≤ 50 行。
- **NFR-2** 搜索/筛选响应 < 300ms（本地已秒级，服务端需索引）。
- **NFR-3** 批次档案导出文件符合食品追溯归档要求，字段不可缺（C2）。
- **NFR-4** 已放行批次的编辑入口须禁用且可见提示「已锁定」。

## 5. 边界与约束（Boundaries & Constraints）

- 批次号规则保持原型风格 `B-YYMMDD-NNN`（如 B-260826-014），须全局唯一且可解析日期。
- 工艺路线 steps 由各产品「配方」定义（见规划模块 recipe-management），批次仅引用，不内联定义。
- 状态机：`running → waiting（待检）→ done（已入库）`；`running → abnormal（异常终止）`；异常须经偏差关闭后方可归档。
- 批次不直接写 SCADA，但开工/完工事件可触发设备占用与释放。

## 6. 成功标准（Acceptance Criteria）

- [ ] 台账五状态分页签计数正确，搜索覆盖批号/产品/设备/配方。
- [ ] 展开行正确渲染工艺路线状态流与批次档案。
- [ ] 异常批次明显标记且无法推进后续工序。
- [ ] 新建批次表单校验配方版本与原料批号后生成批次号。
- [ ] 导出文件含完整批次档案字段。
- [ ] 状态变更留审计日志，已放行批次锁定编辑。

# 配方管理 · 功能规范（spec）

- **模块**：recipe-management
- **对应页面**：`fluxmes/src/pages/Recipes.jsx`
- **依赖**：`specs/constitution.md`
- **版本**：v1.0 · 2026-09-14
- **状态**：Phase 0 已原型实现配方列表与版本历史；本文档确立工业级产品规格

## 1. 概述（Overview）

配方（Recipe / 工艺规程）是流程制造的**工艺权威来源**，定义产品在各工序的投料比例、工艺参数目标值与容差、检验要求。配方以**版本**为单位受控：版本升级须经审批、生效后不可修改、历史批次始终引用当时的生效版本。原型展示配方列表（编号/名称/产品/版本/状态/更新人/更新时间/使用批次数/良品率）与版本历史抽屉；工业级需补齐：草稿—审批—生效—失效生命周期、参数容差与工艺路线绑定、配方下发与执行校验、变更影响分析。

## 2. 用户场景（User Scenarios）

- **US1 · 工艺员查阅配方**：张伟打开 R-CA-001 柠檬酸发酵配方，查看当前生效版本 v3.2 的工艺路线与关键参数（发酵温度 36.5±0.5°C、pH 2.0±0.1）。
- **US2 · 配方升级**（工业级）：工艺部将发酵温度目标由 36.5 调整为 36.8，创建 v3.3 草稿，提交审批。
- **US3 · 审批与生效**（工业级）：技术负责人审批通过 v3.3 并设定生效时间；生效后 v3.2 自动失效，新建批次默认使用 v3.3。
- **US4 · 变更影响分析**（工业级）：配方 v3.3 生效前，系统列出受影响的在制批次（仍执行 v3.2）与需要重评的检验方法。
- **US5 · 配方下发**（工业级）：批次开工时系统将配方参数目标值与容差下发至采集层，超容差自动触发报警。

## 3. 功能需求（Functional Requirements，EARS）

- **FR-1** WHEN 用户进入配方管理，THE SYSTEM SHALL 以表格展示配方列表，列含配方编号、名称、适用产品、当前版本、状态、更新人、更新时间、使用批次数、良品率。
- **FR-2** WHEN 用户点击某配方的「版本历史」，THE SYSTEM SHALL 展示该配方全部版本（版本号/变更说明/变更人/时间/状态）与差异摘要。
- **FR-3** WHEN 用户展开配方，THE SYSTEM SHALL 展示工艺路线（工序序列）与各工序参数目标值、上下限与单位。
- **FR-4**（工业级）WHEN 用户基于某版本创建草稿，THE SYSTEM SHALL 复制该版本的工艺路线与参数并生成新版本号（主版本/次版本递增）。
- **FR-5**（工业级）WHEN 用户提交审批，THE SYSTEM SHALL 将草稿置为「待审批」并冻结编辑（仅审批人可驳回或通过）。
- **FR-6**（工业级）IF 审批通过且到达生效时间，THE SYSTEM SHALL 将新版本置为「生效」并将同配方旧的生效版本置为「失效」。
- **FR-7**（工业级）WHEN 用户查看变更影响，THE SYSTEM SHALL 列出仍在执行旧版本的在制批次与需重评的检验方法。
- **FR-8**（工业级）WHEN 批次开工引用配方，THE SYSTEM SHALL 锁定该批次所用配方版本（快照），后续版本变更不影响在制批次。
- **FR-9**（工业级）WHEN 采集值超出配方参数容差，THE SYSTEM SHALL 生成过程报警并关联至批次与工序。
- **FR-10**（工业级）WHEN 用户执行配方增删改或状态变更，THE SYSTEM SHALL 记录审计日志（C3），含变更前后参数。

## 4. 非功能需求（Non-Functional Requirements）

- **NFR-1** 配方列表在 200 个配方 × 10 版本规模下支持服务端分页，单页 ≤ 50 行。
- **NFR-2** 版本历史按版本号倒序，加载 < 500ms。
- **NFR-3** 生效版本切换为原子操作，不得出现同一配方两个生效版本。
- **NFR-4** 所有历史版本永久留存，满足食品安全追溯与审计要求（C6）。

## 5. 边界与约束（Boundaries & Constraints）

- 配方编号沿用原型风格 `R-<产品族>-<序号>`（如 R-CA-001），版本号 `v<主>.<次>`。
- **生效版本不可修改**，任何改动必须走新版本（数据完整性 C2）。
- 配方变更不得影响已开工批次（版本快照，FR-8）。

## 6. 成功标准（Success Criteria）

| # | 验收项 | 判定方式 |
| --- | --- | --- |
| SC-1 | 列表与版本历史 | 配方列表与版本历史数据正确、按版本倒序 |
| SC-2 | 版本生命周期 | 草稿→待审批→生效→失效流转正确，生效唯一性成立 |
| SC-3 | 审计可追溯 | 任一配方变更可查到 who/when/前后参数 |
| SC-4 | 版本快照 | 配方升级后，在制批次仍引用开工时的版本 |
| SC-5 | 容差报警 | 采集值超容差生成报警并关联批次工序 |

## 7. 依赖与集成点

- **批次管理**：批次引用 `recipe_code` + `recipe_version`（快照，FR-8）。
- **质量管理**：检验方法与判定标准关联配方版本；配方变更触发方法重评。
- **报警中心**：参数容差超限生成过程报警（FR-9）。
- **设备管理**：配方工序绑定设备类别，影响设备可用性校验。

# 报警中心 · 功能规范（spec）

- **模块**：alarm-center
- **对应页面**：`src/pages/Alarms.jsx`
- **依赖**：`specs/constitution.md`
- **版本**：v1.0 · 2026-08-26
- **状态**：Phase 0 原型已实现分级展示、确认交互与趋势/高频源；本文档按工业级产品规格补全报警生命期、SLA 与接入

## 1. 概述（Overview）

报警中心统一接入工艺与设备报警，支持分级（严重/重要/一般）、确认/恢复闭环、趋势与高频源分析，目标是让值班人员快速响应并闭环处理异常。原型声明「报警数据保留 3 年」，并给出响应 SLA 目标（平均 ≤ 5min，含严重 1 条）。工业级需补齐：SCADA/OPC-UA 实时接入、报警生命期状态机、响应 SLA 与升级、确认审计、报警与批次/设备关联。

## 2. 用户场景（User Scenarios）

- **US1 · 报警确认**：张伟在报警列表看到 A-260826-016（F-102 溶氧偏低，major），点击「确认」，状态变为已确认并记录确认人。
- **US2 · 严重升级**：A-260826-017（E-501 加热蒸汽压力高高，critical）长时间未确认，系统按升级策略提醒值班长。
- **US3 · 高频源治理**：近 7 日高频源显示 E-501 浓缩器 5 次，工艺组据此检查蒸汽减压阀 PV-501。
- **US4 · 恢复闭环**：A-260826-013（D-701 出风温度偏差，minor）工况恢复正常，系统标记「已恢复」并记录恢复时间。
- **US5 · 合规留存**（工业级）：所有报警（含确认/恢复/未确认）留存 ≥ 3 年，支持按设备/级别/时间检索。

## 3. 功能需求（Functional Requirements，EARS）

- **FR-1** WHEN 展示报警列表，THE SYSTEM SHALL 以表格列出时间、报警编号、级别、来源设备、内容、触发值/阈值、状态、操作。
- **FR-2** WHEN 报警触发，THE SYSTEM SHALL 按严重（critical）/重要（major）/一般（minor）分级并以对应视觉令牌呈现（原型用 danger/warn/muted）。
- **FR-3** WHEN 用户点击未确认报警的「确认」，THE SYSTEM SHALL 将状态置为已确认（acked）并记录确认人与时间。
- **FR-4** WHEN 报警工况恢复，THE SYSTEM SHALL 将状态置为已恢复（recovered）并记录恢复时间；可系统自动或人工标记。
- **FR-5** WHEN 展示报警趋势，THE SYSTEM SHALL 以按小时、按级别堆叠的条形图呈现。
- **FR-6** WHEN 展示高频报警源，THE SYSTEM SHALL 按近 N 日触发次数降序排列并展示占比。
- **FR-7** WHEN 驾驶舱或顶栏聚合，THE SYSTEM SHALL 展示未确认报警计数（原型侧栏 badge=3、顶栏铃铛=3）。
- **FR-8**（工业级）WHEN 报警产生，THE SYSTEM SHALL 进入「未确认（unacked）」初始态，并按级别启动响应计时（SLA）。
- **FR-9**（工业级）IF 严重（critical）报警在 SLA 内未确认，THE SYSTEM SHALL 触发升级通知（如提醒值班长/短信）。
- **FR-10**（工业级）WHEN 确认/恢复报警，THE SYSTEM SHALL 写审计日志（确认人/时间/前后状态），满足 C3。
- **FR-11**（工业级）WHEN 展示报警，THE SYSTEM SHALL 关联来源设备与（若适用）关联批次，支持跳转设备监控/批次详情。
- **FR-12** WHEN 存储报警，THE SYSTEM SHALL 保留记录 ≥ 3 年，支持检索（C6）。

## 4. 非功能需求（Non-Functional Requirements）

- **NFR-1** 报警从触发到前端可见延迟 ≤ 刷新周期（默认 30s）。
- **NFR-2** 确认操作响应 < 200ms（本地 state 已满足，服务端需乐观更新）。
- **NFR-3** 未确认严重报警须有强提示（脉冲/声音可选），不依赖单一颜色。
- **NFR-4** 大数据量下趋势与高频源聚合查询 < 1s（时间范围可分区）。

## 5. 边界与约束（Boundaries & Constraints）

- 报警优先级：critical > major > minor；critical 必须人工确认，不可自动恢复后静默。
- 报警状态机：`unacked → acked → recovered/closed`；`unacked → recovered`（自动恢复未确认也须留存）。
- 报警来源为设备编码（如 E-501、F-102），来自 SCADA/OPC-UA，MES 不生成工艺报警逻辑（仅展示与编排）。
- 确认动作受 RBAC 约束（constitution C4）：值班长/工艺员可确认。

## 6. 成功标准（Acceptance Criteria）

- [ ] 报警列表分级、确认、恢复交互正确，确认人/时间被记录。
- [ ] 趋势堆叠图与高频源排行数据正确。
- [ ] 未确认严重报警强提示可见，计数在驾驶舱/顶栏一致。
- [ ] 严重报警 SLA 超时触发升级通知。
- [ ] 报警留存 ≥ 3 年且可检索；确认/恢复留审计。

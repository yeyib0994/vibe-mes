# 生产驾驶舱 · 功能规范（spec）

- **模块**：production-cockpit
- **对应页面**：`src/pages/Dashboard.jsx`
- **依赖**：`specs/constitution.md`
- **版本**：v1.0 · 2026-08-26
- **状态**：Phase 0 原型已实现核心展示；本文档按工业级产品规格补全缺口

## 1. 概述（Overview）

生产驾驶舱是 FluxMES 的「首页」，面向值班工艺员与车间管理者，提供一车间实时生产总览：产量达成、批次合格率、OEE、活跃报警，以及生产趋势、罐区设备状态、在制批次与最新报警的聚合视图。目标是在一屏内让值班人员快速判断「当前生产是否健康、哪里需要介入」。

## 2. 用户场景（User Scenarios）

- **US1 · 值班工艺员晨班交接**：陈志远在白班开始时打开驾驶舱，确认夜班产量是否达标、是否有未确认严重报警、在制批次进度是否正常。
- **US2 · 异常介入**：驾驶舱「最新报警」区出现红色脉冲的严重报警（E-501 加热蒸汽压力高高），值班员点击跳转报警中心确认。
- **US3 · 班报产出**：白班结束前点击「生成班报」，系统汇总本班产量、合格、OEE、报警与偏差，导出交接记录。
- **US4 · 多产线切换**（工业级）：车间主任在多个产线间切换，驾驶舱聚合维度随产线变化。

## 3. 功能需求（Functional Requirements，EARS）

- **FR-1** WHEN 用户进入生产驾驶舱，THE SYSTEM SHALL 展示当日产量 KPI（实际产量、日计划、达标进度条与「超/欠时间进度」标记）。
- **FR-2** WHEN 展示生产趋势，THE SYSTEM SHALL 以面积图呈现按小时产出速率，并叠加计划速率参考线（`PLAN_RATE`），标注实际与计划的偏差。
- **FR-3** WHEN 驾驶舱加载，THE SYSTEM SHALL 展示罐区与关键设备列表，每项含设备编码、名称、状态（运行中/清洗/报警/待机）、实时过程参数（温度/pH/转速/压力等）。
- **FR-4** WHEN 展示在制批次，THE SYSTEM SHALL 列出活跃批次的批号、产品、当前工序、所在设备、进度百分比与预计完成时间（ETA）。
- **FR-5** IF 存在未确认（unacked）的严重（critical）报警，THE SYSTEM SHALL 在「最新报警」区以红色脉冲高亮，并提供一键跳转报警中心的入口。
- **FR-6** WHEN 用户点击「刷新」，THE SYSTEM SHALL 重新拉取实时数据并刷新所有卡片；刷新动作应显示加载态且不影响已展开内容。
- **FR-7** WHEN 用户点击「生成班报」，THE SYSTEM SHALL 汇总本班 KPI、在制批次、报警与偏差，生成可导出的班报（PDF/打印）。
- **FR-8** IF 任意实时数据超过其采集周期未更新（默认 30s），THE SYSTEM SHALL 在对应卡片显示降级提示（如「数据延迟」），且不展示可能误导的陈旧值。
- **FR-9**（工业级）WHEN 驾驶舱加载，THE SYSTEM SHALL 支持按车间/产线维度筛选与切换，KPI 与图表随维度联动。
- **FR-10**（工业级）WHEN 展示 OEE，THE SYSTEM SHALL 分解为「时间开动率 × 性能开动率 × 合格品率」并分别呈现，口径可追溯至原始记录。
- **FR-11**（工业级）WHEN 用户自定义驾驶舱，THE SYSTEM SHALL 允许配置可见 KPI 卡片与排序，配置随用户保存。

## 4. 非功能需求（Non-Functional Requirements）

- **NFR-1** 驾驶舱首屏渲染 < 1.5s（生产构建）。
- **NFR-2** 实时数据刷新周期 ≤ 30s，且刷新不打断用户滚动/展开状态。
- **NFR-3** 深色为默认主题；浅色主题下所有 KPI 对比度满足 WCAG 2.1 AA。
- **NFR-4** 状态传达不使用「仅颜色」：设备/报警状态须同时配文字或图标（原型已用 Dot + 文字，保持）。
- **NFR-5** 接口失败时卡片进入降级态而非整页白屏。

## 5. 边界与约束（Boundaries & Constraints）

- 驾驶舱为**只读聚合视图**，不直接编辑批次或确认报警（确认动作在报警中心完成，原型通过跳转实现）。
- 产量/合格率/OEE 的计算口径由后端服务层统一提供，前端不得自行重算（避免多端口径不一致）。
- 设备实时参数来自 SCADA/OPC-UA，MES 仅展示，不控制。
- 原型当前数据为 `src/data/mes.js` 静态值，Phase 1 起经 `src/api` 服务层替换。

## 6. 成功标准（Acceptance Criteria）

- [ ] 四个 KPI 卡片（产量/合格率/OEE/活跃报警）数据可被单一服务接口驱动，且含达标/超期标记。
- [ ] 生产趋势面积图正确叠加计划线，悬停显示实际值与计划值。
- [ ] 设备状态列表 8 台设备的状态与参数可由实时接口更新。
- [ ] 存在未确认严重报警时，「最新报警」区脉冲高亮且跳转可用。
- [ ] 数据超期（>30s）时降级提示可见。

## 7. 现状对照（Prototype vs Industrial Gap）

| 能力 | 原型现状 | 工业级缺口 |
| --- | --- | --- |
| KPI 展示 | ✅ 静态值 | 接 API、口径统一 |
| 生产趋势 + 计划线 | ✅ 静态 | 实时刷新、多产线 |
| 设备状态列表 | ✅ 静态 8 台 | SCADA 实时接入、状态机 |
| 在制批次 | ✅ 静态 4 条 | 服务端分页/过滤 |
| 最新报警跳转 | ✅ 前端跳转 | 未确认计数实时 |
| 生成班报 | ❌ 仅按钮 | 班报模板 + 审计留痕 |
| 多产线切换 | ❌ | 维度筛选 |
| KPI 自定义 | ❌ | 用户配置持久化 |

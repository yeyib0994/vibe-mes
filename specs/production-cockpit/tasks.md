# 生产驾驶舱 · 任务清单（tasks）

- **模块**：production-cockpit
- **对应 plan**：`specs/production-cockpit/plan.md`
- **优先级**：P0 = 必须（Phase 1 落地）；P1 = 重要；P2 = 增强
- **图例**：✅ 已原型实现（Phase 0）

## 任务

### T1 · 抽取数据服务层（P0）
- 目标：建立 `src/api/dashboard.js` 的 `getCockpit(siteId)`，Phase 0 返回 Mock，页面从 `src/data/mes.js` 解耦。
- 验收：Dashboard 不再直接 import `mes.js` 具体数组；通过服务函数取数；Mock 与真实实现可切换。

### T2 · 接入实时刷新（P0）
- 目标：用 TanStack Query 每 30s 重拉驾驶舱数据，保持展开/滚动态。
- 验收：点击刷新或自动周期后数据更新；用户已展开的行不收起；接口失败卡片降级而非白屏。

### T3 · 时效降级提示（P0）
- 目标：依据 `generatedAt` 实现 spec FR-8，超 30s 显示「数据延迟」且不明示陈旧值。
- 验收：人为将 Mock 的 `generatedAt` 置为 60s 前，对应卡片出现降级态。

### T4 · 未确认严重报警高亮跳转（P0）✅
- 目标：固化原型已有的「最新报警」脉冲高亮 + `onNavigate('alarms')` 跳转；数据改为实时未确认计数。
- 验收：存在 unacked critical 时红色脉冲可见；点击跳转报警中心且过滤未确认。

### T5 · 产量/合格率/OEE 口径后端化（P1）
- 目标：聚合计算移至后端，前端仅渲染；OEE 分解为可用率×性能×合格（FR-10）。
- 验收：驾驶舱、批次、质量三处合格率数值一致；OEE 三因子可分别下钻。

### T6 · 生成班报（P1）
- 目标：实现 `spec FR-7`，汇总本班 KPI/批次/报警/偏差并导出；写审计日志。
- 验收：点击生成可导出的班报；审计表存在 who/when/班次记录。

### T7 · 多产线维度切换（P2）
- 目标：实现 FR-9，按车间/产线筛选，KPI 与图表联动；受 RBAC 约束。
- 验收：切换产线后所有卡片数据联动；无权限产线不可见。

### T8 · KPI 卡片自定义（P2）
- 目标：实现 FR-11，用户可配置可见卡片与排序并持久化。
- 验收：配置保存后刷新仍生效；默认布局可重置。

## 进度总览
- Phase 0 已实现：FR-1~FR-7 静态展示、FR-5 跳转。
- Phase 1 关键路径：T1 → T2 → T3 → T4（实时化与降级）→ T5/T6（口径与班报）。
- Phase 2 增强：T7/T8。
